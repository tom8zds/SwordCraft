# 模型辅助像素资产生产流程

## 决策

正式美术应使用图像模型生成候选稿。原因：目标是高细节 HD-2D 像素画，包含复杂砖石、锻造金属、武器结构和场景材质；纯代码几何无法以合理成本达到该质量。

但不能把文生图结果原样投入 PixiJS。模型擅长构图和材质候选，不擅长可靠的透明背景、像素网格、固定尺寸、统一视角、逐帧一致性、锚点和碰撞边界。

## 技术框架

- 资产逻辑基准：`640 × 360` 场景画布。
- 单体英雄资产先以 4 倍工作分辨率生成，再规范化到目标像素尺寸。
- 贴图过滤：`nearest`；不得将带双线性模糊的“伪像素画”直接交付。
- 光源：左侧炉火是唯一主要暖光源，受光和阴影遵循同一空间位置；弱环境光维持暗部可读性，不额外生成斜射光束或蓝紫发光边。
- 视角：固定正面正交投影，无消失点、远近缩放、侧墙收缩、广角或三分之四视角；建筑为砖顶、砖墙、石地面，木材仅限工作台等家具。
- 展示区仅有一行直接固定在砖墙上的金属双挂钩，等间距随房间向右延伸，不生成多排、展示架、搁板或木背板。运行时砖墙、地面、炭炉、工作台、挂钩和剑属于同一个世界根节点，由镜头整体横向浏览；只有 HUD 固定。挂钩图层保留透明以便交互，但不得独立滑动或携带矩形砖墙底板。
- 优先生成统一构图，再按 API 返回的图层边界还原到共同画布，避免独立生图的视角与光照漂移。
- 动态概率圆环不属于生成资产，运行时由 PixiJS 根据真实权重绘制并叠加在锤头预留槽中。
- 第一版火炉使用两张完整静态图：有火和无火。炉体与炉火不再拆成两层，也不制作炉火动画。

## 生产步骤

1. **生成风格母图**
   - 使用完整铁匠铺场景提示词生成 4～8 张候选。
   - 选择一张作为唯一风格母图，锁定砖块尺度、像素密度、轮廓、灯光和综合色板。
2. **生成英雄资产族**
   - 以风格母图作为图像参考，分别生成火炉、锤子、基础铁剑。
   - 每个资产只保留游戏中的固定正面正交视图，统一朝向、比例和光源；不生成无用途的转面或三分之四透视。
3. **受控编辑**
   - 锤头强制保留一个清晰、正圆、无遮挡的嵌槽，供运行时概率圆环覆盖。
   - 武器变体以已批准基础剑为参考图进行编辑，单次只改变一个进化维度。
4. **规范化**
   - 去背景并检查 alpha；修整半透明边缘。
   - 最近邻缩放到目标尺寸。
   - 限制色板，修复亚像素、随机噪点、色带和断裂轮廓。
   - 统一画布、底部/握持锚点和光源方向。
5. **静态状态制作**
   - 火炉直接生成有火和无火两张完整图。
   - 两张图必须使用同一画布、同一镜头、同一锚点和同一物件轮廓，只改变炉膛内的火焰与光照状态。
   - 不生成独立炉火层、spritesheet 或逐帧动画。
6. **技术 QA**
   - 执行像素尺寸、alpha、色数和透明边界检查。
   - 建立最近邻预览；在真实铁匠铺背景上按实际比例预览两种火炉状态。
7. **PixiJS 接入**
   - 通过 `Assets` 清单加载静态纹理对；不为火炉制作 spritesheet。
   - 贴图 `source.scaleMode = 'nearest'`。
   - 资产精灵与动态圆环、Bloom、粒子和点击区域分层；火炉只在两个静态纹理之间切换。
8. **游戏内验收**
   - 在 1280×720、移动横屏和高 DPR 下检查清晰度、拖拽命中与两种静态状态切换。
   - 只有游戏内实际画面通过后，资产状态才能从 `candidate` 改为 `approved`。

## 首批目标尺寸

| 资产 | 工作输出 | 规范化目标 | 锚点 |
|---|---:|---:|---|
| 完整铁匠铺背景层 | 2560×1440 | 640×360 | 左上 |
| 火炉主体 | 1024×1024 | 176×236 | 底部中心 |
| 完整火炉状态图 | 2048×1152 候选 | 中央提取后保持同一锚点 | 火炉底部中心 |
| 大型锻造锤 | 1024×1024 | 176×244 | 握柄尾端/旋转枢轴 |
| 基础铁剑 | 1024×1024 | 48×176 | 握柄中心 |
| 工作台铁剑详情预览 | 共用基础剑 | 2×最近邻显示 | 同基础剑 |

## 不可接受结果

- 背景自带文字、标签、UI 或水印。
- 像素大小不一致、边缘带抗锯齿、细节像照片缩小而不是像素簇。
- 锤头圆环被烘焙成固定概率。
- 有火/无火两张图中的炉体、燃料、相机或光源位置漂移。
- 剑的护手、刃长或握柄在同一进化族中无规则漂移。
- 仅通过换色声称完成进化。
